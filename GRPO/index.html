GRPO：从架构到每一个 Train Step

从同一 Prompt 的多条 Responses 入手，看整段 Reward 如何广播到 Tokens，并逐行拆解 IS / Clipping / Reference KL。

一句话：GRPO 用同 Prompt 的多个 Responses 比较 Reward 形成 Group Advantage，去掉 Critic；但每个生成 Token 仍然有独立的 Ratio、Clipping 项和梯度。

ARCHITECTURE

一个 Trainable Actor + 一个可选 Frozen Reference；没有 Critic

Prompts → Old Actor → 每个 Prompt G 个 Responses
↓
Reward Function

每个完整 Response 得到 Ri → 组内均值/标准差 → Ai。

Old / Reference

Old 对应本轮采样、用于 IS；Reference 长期冻结、用于可选 KL 正则化。

↓
Token-wise Ratio + Broadcast Advantage + Clip + β KL → Actor Adam

本教程展示经典 GRPO-Clip + 可选 Reference KL。Reference KL 不是 GRPO 必需项：β=0 时可以不创建 Reference 模型。

01 / GROUP ROLLOUT

同一 Prompt 采样多个完整答案

# [B] prompts → [B*G, L] completion tokens
prompts_repeated = repeat_each_prompt(prompts, group_size=4)
with torch.no_grad():
    completions = actor.generate(prompts_repeated)
    old_log_probs = actor.log_probs(prompts_repeated, completions)

例如 Prompt “法国首都？”得到 4 条 Responses：Paris、London、Paris in France、Berlin。生成时必须保存对应 Token 的 Old Log Probability。

02 / GROUP ADVANTAGE

整段 Response 打分 → Group Relative Advantage

# 假设同一组 Rewards = [1, 0, 1, 0]
rewards = torch.tensor([1., 0., 1., 0.])
mean = rewards.mean()                          # 0.5
std = rewards.std(unbiased=False)              # 0.5
advantages = (rewards - mean) / (std + 1e-8)
# [ +1, -1, +1, -1 ]，shape [B*G]

Reward 通常来自完整 Response 的结果正确性、规则检查或 Reward Model。GRPO 不在每个 Token 上训练 V(s)，因此不需要 Critic/GAE。

如果一组 Rewards 全相同，组内标准化 Advantage 会变为 0（通常加 epsilon 防止除零）；这一组对 Clipped Policy Objective 不提供有效梯度。
03 / CREDIT ASSIGNMENT

Whole-Response Advantage 怎么变 Per-Token？

Response 1：Paris is correct

Reward 1 → Advantage +1 → 三个 Tokens 的 Advantage 均为 +1。

Response 2：London is wrong

Reward 0 → Advantage −1 → 三个 Tokens 的 Advantage 均为 −1。

# advantages [B*G]
token_adv = advantages[:, None]  # [B*G,1]
# 和 ratio [B*G,L] 相乘时广播

这不是识别“哪个 Token 真正导致 Reward”。它只是把同一整段回答的质量信号分配到每个生成位置。每个 Token 的 logπ 梯度仍然不同。

05 / TOKEN IMPORTANCE WEIGHTS

每个 Token 自己的 Ratio 和 Clip

current_log_probs = actor.log_probs(prompts, completions) # [B*G,L]
ratio = torch.exp(current_log_probs - old_log_probs)
adv = advantages[:, None]                               # [B*G,1]
surr1 = ratio * adv
surr2 = ratio.clamp(1-eps,1+eps) * adv
clipped_objective = torch.minimum(surr1, surr2)          # [B*G,L]

假设某个正 Advantage Response 的 Tokens 的 Ratio 是 [1.5,1.1,0.9]；ε=.2；Clip 后每个 Token Objective 分别为 [1.2,1.1,0.9]。第一个 Token 超过上界，不再奖励继续增加概率。

06 / REFERENCE KL

为什么 IS 已经有 Ratio，仍然可加 Reference KL？

IS 比较 Current / Old（本轮）；Reference KL 比较 Current 与固定的初始 SFT 基准（长期）。两个比值来自不同的分母。

d = ref_log_probs - current_log_probs
kl_token = torch.exp(d) - d - 1
# d = log(P_ref / P_current)
# KL estimator per sampled completion token
# 对从 Current 分布采样时，其期望对应 KL(Current || Ref)

固定 Reference P(token)=0.30；样本级 KL = 。不是整个 Vocabulary 的精确 KL。

在旧策略 Rollout 上复用样本时，严格的无偏估计条件不再自动成立；这里作为训练中的样本级正则项。β=0 可以完全关闭。

07 / AGGREGATION

先算 Per-Token Loss，再聚合 Response

# completion_mask [B*G,L]：有效 Token 为 1
per_token_loss = -clipped_objective + beta * kl_token
response_loss = (
    (per_token_loss * completion_mask).sum(dim=1)
    / completion_mask.sum(dim=1).clamp(min=1)
)                                   # [B*G]
loss = response_loss.mean()         # scalar

不同 GRPO 实现有不同的 Loss Normalization（按 Response 长度 / 固定最大长度 / 全局 Token 数），可能影响长短回答的梯度权重。上面明确使用 每条 Response 内先平均、再跨 Responses 平均 的示意。

08 / OPTIMIZER

只有 Actor Backprop，没有 Critic Step

for epoch in range(num_epochs):
    current_log_probs = actor.log_probs(prompts, completions)
    # 重新算 Ratio、Clip、KL、Masked Loss
    optimizer.zero_grad()
    loss.backward()
    torch.nn.utils.clip_grad_norm_(actor.parameters(), 1.0)
    optimizer.step()
# 下轮更新后重新生成 Responses，刷新 Old Log Probs
以上是分步教学伪代码：每个 Epoch 必须重新计算 loss 和计算图；不能拿旧 loss 重复 backward。Grad norm clipping 与 ratio clipping 是两种不同操作。
