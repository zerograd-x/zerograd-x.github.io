TRPO · 完整 Training Flowchart

① Old Actor（固定参数）→ 环境采样 Rolloutstates, actions, rewards, old_action_dists, old_log_probs
↓
② Critic Forward → TD Errors → GAE Advantage先算 Advantage；不要求先 Critic Backward
↓
③ Critic Loss → Backward → Adam Step更新 φ；通常可与 Actor 优化调换顺序
④ Surrogate: IS(Current / Old) × Advantage取得 Actor Gradient g
↓ Actor 分支
⑤ KL(Old || Current) Hessian-vector product描述策略变化的局部曲率；不是 Reference KL
↓
⑥ Conjugate Gradient → Candidate Step
↓
⑦ Backtracking Line Search验证 KL ≤ δ 且 Surrogate Improvement > 0；失败缩步
↓
⑧ 接受候选后写回 Actor 参数 θ；否则不更新
↻
新 Actor 收集下一批 Rollout → 刷新 Old Policy
与 PPO、GRPO 并排比较 →
ONE UPDATE AT A TIME

TRPO：沿着一次训练，
看 Weight 怎么更新。

不先背算法公式。假设我们已经有一个 Actor 和一个 Critic，下面严格按照一次 update(transition_dict) 的执行顺序来讲：输入是什么、执行哪段代码、得到什么、哪些 Weight 真正变了。

先记住：一轮 TRPO 中，Actor 只在最后接受候选参数时才真正更新。Critic 通过 Adam 单独更新。KL 不是决定丢不丢 Rollout，而是限制这轮 Actor 可以改变多少。
本轮执行顺序：
0. 初始网络1. Rollout2. TD & GAE3. 冻结旧概率4. Critic Adam5. Surrogate Gradient6. KL Hessian7. CG8. Candidate Step9. Line Search10. 写回 Actor
TRAIN STEP 00

准备：两个网络，两个参数集合

Actor θ
输入 State，输出所有 Action 的概率。例如 [0.6, 0.4]。负责采样 Action。
Critic φ
输入 State，输出一个 Value。例如 4.0。负责估计未来 Return。
self.actor = PolicyNet(...).to(device)
self.critic = ValueNet(...).to(device)
self.critic_optimizer = torch.optim.Adam(
    self.critic.parameters(), lr=critic_lr
)
Weight 状态：Actor θ 未更新；Critic φ 未更新。Actor 不使用 Adam，Critic 使用 Adam。
TRAIN STEP 01 · COLLECT

旧 Actor 生成 Rollout

在一轮采样中，Actor 参数暂时固定。每次拿到 State，用 take_action() 根据概率随机抽 Action；环境返回 Reward 和 Next State。

probs = self.actor(state)               # 例如 [0.6, 0.4]
dist = torch.distributions.Categorical(probs)
action = dist.sample()                  # 比如采到 Action 0
# environment.step(action) -> reward, next_state, done

收集完得到 states, actions, rewards, next_states, dones。不是每个 token/step 都立刻更新 Actor，而是先完成这批 Rollout。

Weight 状态：Actor θ 不变；Critic φ 不变。输出是一批 Transition 数据。
TRAIN STEP 02 · ADVANTAGE

用 Critic 计算 TD Error，再用 GAE 得到 Advantage

训练需要区分“某个 Action 是否比平均表现更好”。Critic 提供 Value 预测；Reward 加上下一状态 Value 构成 TD Target，再减去当前 Value 得到 TD Error。

td_target = rewards + gamma * critic(next_states) * (1 - dones)
td_delta = td_target - critic(states)
advantage = compute_advantage(gamma, lmbda, td_delta.cpu())

例如当前奖励 1、下一状态预测 5、当前状态预测 4、γ=0.9，则 TD Error = 1 + 0.9×5 − 4 = 1.5。

GAE 的 λ 干什么？决定 Advantage 有多大程度依赖更远的实际 TD Error，而不是在近期就使用 Critic 预测。γ 定义长期 Reward 折扣，不能简单用小 γ 替代 λ。

假设 TD Errors 为 [1, 2, 3]、γ=0.9，则第 0 步的 GAE Advantage 为 。

Weight 状态：两个网络仍未更新。我们只是获得固定的 Advantage 数值，后面 Actor 不会反向传播更新 Critic。
TRAIN STEP 03 · SNAPSHOT

保存 Old Policy 概率

Rollout 是旧 Actor 采集的，因此我们必须把旧概率留住。后面 Candidate Actor 变了，分母仍然不变。

old_action_dists = Categorical(
    probs=self.actor(states).detach()
)
old_log_probs = old_action_dists.log_prob(
    actions.squeeze(1)
).unsqueeze(1)
变量实际存什么后面在哪里用
old_log_probs每个采样 Action 对应的 log probabilityImportance Ratio
old_action_dists每个 State 下所有 Action 的概率KL
Weight 状态：Actor 和 Critic 均未变。detach() 只是阻断旧概率的计算图，不是更新网络。
TRAIN STEP 04 · CRITIC UPDATE

Critic 先用 Adam 更新一次

Critic 预测的 Value 与 TD Target 比较，MSE Loss 通过 Backpropagation 更新 Critic 参数。你给的实现是在完成 Advantage 估计后才执行这一段，因此本批次 Advantage 已经固定。

critic_loss = F.mse_loss(critic(states), td_target.detach())
critic_optimizer.zero_grad()
critic_loss.backward()
critic_optimizer.step()       # ← 这行真正修改 Critic φ
Weight 状态：Critic φ 已更新；Actor θ 还没有更新。后续 TRPO 处理的是 Actor。
TRAIN STEP 05 · POLICY GRADIENT

计算 Surrogate Objective 和 Actor Gradient

现在使用固定的 Rollout Actions、Advantage 和旧概率，重新查询当前 Actor 对这些 Actions 的概率。

log_probs = torch.log(actor(states).gather(1, actions))
ratio = torch.exp(log_probs - old_log_probs)
surrogate_obj = (ratio * advantage.detach()).mean()
grads = torch.autograd.grad(surrogate_obj, actor.parameters())
g = torch.cat([x.reshape(-1) for x in grads]).detach()

关键疑问：Actor 还没更新，Ratio 不就是 1 吗？是的。初始时新旧概率相等，所以 Ratio 的当前数值是 1。但它仍然是参数 θ 的函数，我们求的是“如果稍微改变 θ，Ratio 会怎么变化”。其导数通常非零。

Advantage 为正，梯度倾向于增加被采样 Action 的概率；Advantage 为负，则倾向降低。由于网络参数共享，最终各 Action 的概率变化并不是独立的。

Weight 状态：Actor θ 仍不变。autograd.grad() 只返回 Gradient，不是 optimizer.step()。
TRAIN STEP 06 · KL CURVATURE

通过 KL 的二阶信息，判断哪些 Weight 更敏感

如果两个 Weight 有相同的原始 Gradient，一个 Weight 轻微改变就会让输出概率跳很大，另一个却不会。TRPO 不希望一视同仁。它使用 KL Hessian 描述这种敏感程度。

new_action_dists = Categorical(self.actor(states))
kl = kl_divergence(old_action_dists, new_action_dists).mean()
kl_grad = torch.autograd.grad(
    kl, self.actor.parameters(), create_graph=True
)
flat = torch.cat([v.reshape(-1) for v in kl_grad])
scalar = torch.dot(flat, vector)
Hv = torch.autograd.grad(scalar, self.actor.parameters())

KL 此时也是 0，为什么还可以用？因为 TRPO 用的是 KL 的二阶导数。例如函数 x² 在 x=0 时数值和一阶导都为 0，但二阶导等于 2。

不用存下完整 Hessian 矩阵。只需输入一个向量 v，计算 H 与 v 的乘积（Hessian-vector Product），就能供下一步 CG 使用。
Weight 状态：Actor θ 不变，只计算 KL 对 Weight 变化的局部敏感程度。
TRAIN STEP 07 · CG

Conjugate Gradient 只负责找方向，不负责更新网络

输入：刚才的 Policy Gradient g，以及能够执行 H @ v 的函数。CG 迭代求解 H x = g，最后返回一个经过 KL 曲率调整的方向 x。

普通 Gradient
g = [1, 1]
假设 KL 曲率对角为 [100, 1]
CG 得到 x = [0.01, 1]

第一个参数对 Policy 变化非常敏感，因此即使原始 Gradient 相同，TRPO 给它更小的相对更新分量。

# 简化的调用逻辑
direction = conjugate_gradient(
    policy_gradient=g,
    matrix_vector_product=hessian_matrix_vector_product
)
# direction ≈ H^{-1} g
# 此时没有 Actor Weight Update

实际 CG 通过迭代 Residual、Search Direction 和 HVP 求解；实践中常对 Hessian 加 Damping，以防不稳定。

Weight 状态：Actor θ 不变；我们现在只得到“沿哪个方向尝试更新”。
TRAIN STEP 08 · CANDIDATE STEP

根据 KL Threshold，算出最多尝试多大的参数步长

有方向还不够。TRPO 用 KL 的局部二阶近似计算可接受的候选步长尺度。这里的 kl_constraint 控制的是 Policy Distribution 的变化，不是普通 Adam Learning Rate。

Hd = hessian_matrix_vector_product(states, old_dist, direction)
max_coef = torch.sqrt(
    2 * kl_constraint / (torch.dot(direction, Hd) + 1e-8)
)
candidate_step = direction * max_coef

例如方向为 [0.01, 1]，若缩放系数是 0.1，候选更新就是 [0.001, 0.1]。这是候选值，不是已经接受的更新。

Weight 状态：Actor θ 仍不变。候选步长已经算好，下一步才会试。
TRAIN STEP 09 · BACKTRACKING

在 Actor 副本上试候选权重，过大就缩小

old_weights = parameters_to_vector(actor.parameters())
for i in range(15):
    coef = alpha ** i        # 例如 1, .5, .25, .125 ...
    trial_weights = old_weights + coef * candidate_step
    trial_actor = copy.deepcopy(actor)
    vector_to_parameters(trial_weights, trial_actor.parameters())
    # 检查 KL(old, trial) 和 Objective(trial)
    if kl_ok and objective_improves:
        return trial_weights
return old_weights           # 所有尝试都失败则不更新

所以，alpha 是 Line Search 的缩步系数，并非 Actor 的 Adam Learning Rate。KL 超标通常是缩小参数更新，不是丢弃本批 Rollout。

注意：必须同时满足 KL < threshold 和 new objective > old objective。没有通过，就继续缩小，直到接受或放弃。

Weight 状态：真正的 Actor θ 仍不变；只是临时的 Actor 副本在尝试。
TRAIN STEP 10 · COMMIT UPDATE

终于真正更新 Actor Weight

new_para = line_search(...)
torch.nn.utils.convert_parameters.vector_to_parameters(
    new_para, self.actor.parameters()
)    # ← 唯一将已接受参数写回实际 Actor 的地方

若 Line Search 接受 Candidate，这行写入新的 Actor Weight；若所有尝试失败，new_para 等于旧参数，这行实际上不会改变 Actor。

然后下一轮训练：用更新后的 Actor 重新收集数据，重新计算 Advantage 和 Policy Gradient。旧概率快照也需要重新建立。

Weight 状态：Critic 在 Step 04 已更新；Actor 在本步才有可能更新。至此完整一次 TRPO Train Step 结束。

为什么 TRPO 不直接用 Adam + 小 Learning Rate？

因为 Learning Rate 控制参数更新大小，而 Policy 的输出分布可能对不同参数有不同敏感度。TRPO 的 KL Hessian 调整方向，KL Threshold 缩放步长，Line Search 检查实际 KL 与 Surrogate Improvement。Adam 本身没有这个约束。

与 PPO-Clip 对比

PPO-Clip 通常利用 clipped probability-ratio objective，并使用 Adam 更新 Actor；可以附加 KL early stopping。TRPO 显式优化带平均 KL 约束的 surrogate，使用二阶局部近似、CG 和 Line Search。PPO 的 clip 并不等于严格 KL 限制。

这段教学代码的实际边界

GAE 应在真正的 Episode 结束处重置；超时截断与终止要分清。CG 通常需要 Hessian Damping 和数值保护。训练时应保存 Old Policy Snapshot，并确保采样期间参数固定。有限样本的 Surrogate 改善不等于保证真实 Return 一定提高。
