07 / TRUST REGION POLICY OPTIMIZATION

知道往哪走，
还要知道走多远。

TRPO 没有神秘的新奖励。Rollout 和 Advantage 仍然告诉 Actor 哪些动作值得强化；真正不同的是：更新权重时，TRPO 会先考虑新旧 Policy 的差异，再决定更新方向与幅度。

普通 Policy Gradient + Adam

Rollout → Advantage → Gradient → Adam 更新 Weight。

Learning Rate 调节参数步长，但不能直接保证输出的动作概率变化很小。

TRPO

Rollout → Advantage → Gradient → 根据 KL 调整方向 → 检查 KL → 更新 Weight。

不是简单的“KL 超标就丢弃 Rollout”，而是先缩小候选参数更新。

01 · 把一轮训练走完

旧 Policy π_old
↓
采集 Rollout，得到 reward 和 action
↓
Critic 估计 Advantage（常用 GAE）
↓
计算 Surrogate Objective 的梯度 g
↓
利用 KL 二阶信息求调整后的方向（Conjugate Gradient）
↓
生成候选 Weight Update
↓
Line Search：KL 够小，并且 Objective 改善吗？
↓
接受更新 / 缩小步长重试 / 保留旧参数
↓
新 Policy → 收集新 Rollout

特别注意执行顺序：计算梯度时还没有更新 Actor，所以当前与旧 Policy 相同，probability ratio 等于 1；但 ratio 对 Weight 的导数不为零。等得到 Candidate Weights，ratio 才可能偏离 1。

02 · 为什么同时保存 old_log_probs 和 old_action_dists？

old_log_probs：只保存实际采样到的 Action 在旧 Policy 下的 log probability，用于 Importance Ratio。

old_action_dists：保存每个 State 下所有 Action 的概率分布，用于计算 KL。

old_dist = Categorical(probs=actor(states).detach())
old_log_probs = old_dist.log_prob(actions)

两个值可以从同一次 Actor Forward 得到，不必重复跑两次网络。

05 · 只留两个必要公式

优化信号
ratio = exp(new_logp - old_logp)
objective = mean(ratio * advantage)

Advantage 为正，希望增加该 Action 概率；为负，希望减少。旧参数处 ratio=1，但仍然可求梯度。

更新约束
candidate = old_weights + step
accept if (
    objective_improves
    and mean_kl <= threshold
)

这两项只是直觉级伪代码。实际 TRPO 的 step 来自 KL 二阶近似和 Conjugate Gradient，并通过 Backtracking 缩小。

06 · KL 和 Learning Rate 到底什么关系？

标准 TRPO 不依赖普通 Adam Learning Rate 更新 Actor。它先利用 KL Hessian 改变梯度方向，再根据 KL Threshold 缩放候选步长。line_search 中的 alpha 是步长缩减因子，不是 Adam 的 Learning Rate。Critic 仍然可以使用 Adam。

展开：为什么不能只检查 KL，还是需要 Hessian？

两个 Weight 的梯度可能相同，但它们改变 Action Probability 的敏感度不同。KL Hessian 告诉 TRPO 哪些组合会让 Policy 改变得更剧烈。它还能表示不同参数之间的耦合，因此更新方向不一定与原始梯度平行。Line Search 负责最终验收。

展开：GAE 的 gamma 与 lambda 各做什么？

Gamma 定义未来 Reward 的折扣，因此也定义优化目标。Lambda 只改变 Advantage 估计中真实后续奖励与 Critic 预测的折中。减小 gamma 会改变任务偏好；减小 lambda 不等价于改变 gamma。

展开：为什么说 TRPO 比 PPO 更“严格”？

TRPO 显式检查候选更新的平均 KL，并使用受约束的二阶近似来选步长。PPO-Clip 通常用 Adam 优化 clipped surrogate，并可选择监控 KL 或提前停止。PPO 的 clipping 本身并不严格保证 KL 阈值不被超过。TRPO 对平均 KL 的检查也不等于每个 State 都得到严格的理论保证。

07 · 建议学习顺序

先理解 Ratio 在旧参数处为 1 但梯度不为零，再理解 KL Hessian 改变方向，最后理解 Line Search 只在满足 KL 且 Objective 改善时接受参数。理解这三个点，TRPO 的执行顺序就清楚了。

09 · 先算 Ratio，再算 Gradient：时间顺序一点也不矛盾

时刻 A（刚采完 Rollout）：old_log_probs 来自旧策略，保存下来并 detach。此时当前 Actor 参数也等于旧参数，所以 Ratio 对每个采样 Action 都是 1。

时刻 B（求 Gradient）：我们对“若 Weight 稍微变化，Ratio 会怎样变化”求导。当前 Ratio=1，不意味着 Ratio 的斜率=0。

# old_log_probs 不随优化参数改变
current_logp = actor(states).log_prob(actions)
ratio = (current_logp - old_log_probs).exp()  # 初始值约为 1
objective = (ratio * advantages).mean()
g = torch.autograd.grad(objective, actor.parameters())
# 这里只求梯度，没有执行 optimizer.step()，Weight 不变

时刻 C（尝试 Candidate）：把暂时算出的新 Weight 放进 Actor 副本。再次计算 Ratio，它才可能从 1 变成 1.2 或 0.8。此时用于检查“改完是否更好”，而不是重新生成 Rollout。

10 · Critic 和 GAE：为什么先有 Advantage 才能优化 Actor？

Critic 预测从 State 出发的未来 Return；它不负责选择 Action。Rollout 的每一步都有 Reward，而 Critic 会对当前 State 和下一 State 给出预测。

# 一个非终止 Transition
reward = 1.0
gamma = 0.9
value_now = 4.0
value_next = 5.0
td_error = reward + gamma * value_next - value_now  # 1.5

1-step TD Error 可以直接当作 Advantage 的估计，但会依赖 Critic 的准确性。GAE 从后往前累加 TD Error：越远的 TD Error，权重通常越低。

11 · 为什么要用 KL Hessian，而不是只用 Learning Rate？

假设两个 Weight 的 Policy Gradient 都是 1。普通 SGD 倾向于同时增加它们。但其中一个 Weight 的轻微变化可能让输出概率剧烈变化，另一个 Weight 则不敏感。

为方便手算，设 Gradient 为 [1, 1]，KL Hessian 是一个对角矩阵，对角线为 [100, 1]。

参数原始 GradientKL 敏感程度调整后的方向
w₁1100（敏感）0.01
w₂11（不敏感）1

这就是为什么 TRPO 的方向可能不同于普通梯度：它试图用有限的 Policy Distribution Change 换取更多的 Objective Improvement。 实际 Hessian 还含有非对角项，因此参数之间可能互相影响。

12 · Hessian-vector Product 到底计算了什么？

如果 Actor 有百万参数，完整 Hessian 就有万亿个元素，没有必要把它保存下来。TRPO 只需要一个服务：给它向量 v，返回 H @ v。

def hvp(actor, states, old_dist, vector):
    new_dist = actor(states)
    kl = kl_divergence(old_dist, new_dist).mean()
    first = torch.autograd.grad(
        kl, actor.parameters(), create_graph=True
    )
    flat_first = torch.cat([x.reshape(-1) for x in first])
    directional_derivative = (flat_first * vector).sum()
    second = torch.autograd.grad(
        directional_derivative, actor.parameters()
    )
    return torch.cat([x.reshape(-1) for x in second])

第一次求导得到 KL 的 Gradient；与给定向量做点积；再求一次导就得到 H @ v。这并没有修改 Actor 参数。示例假设 actor(states) 返回分布对象。

13 · Conjugate Gradient（CG）在做什么？

我们已经有 Policy Gradient g，希望得到经过 KL 调整的方向 x，满足 H x = g。CG 不是更新神经网络的 Optimizer；它只是在求一个线性方程的近似解。

初始：x=0，Residual r=g，意思是还没有满足 Hx=g。

每轮：调用 HVP 得到 Hp；根据 Residual 选择搜索步长；改进 x；重新计算 Residual。

结束：Residual 足够小，或达到迭代上限，返回方向 x。真实实现通常对 HVP 加 Damping，并处理数值异常。

x = zeros_like(g)
r = g.clone()
p = r.clone()
for iteration in range(10):
    Hp = hvp(p)               # 不构造完整 H
    step = dot(r, r) / dot(p, Hp)
    x = x + step * p
    r_new = r - step * Hp
    if dot(r_new, r_new) < tolerance:
        break
    p = r_new + (dot(r_new, r_new) / dot(r, r)) * p
    r = r_new
# x 是方向，不是已经更新好的网络

14 · Candidate Step 与 Line Search：什么时候真正改 Weight？

有了 CG 返回的方向，还不能直接改 Weight。首先按 KL Threshold 缩放这个方向，形成候选步长，再用 Line Search 在 Actor 副本上试验。

假设当前 Weight 是 [0.50, 0.20]，Candidate Step 是 [0.02, 0.10]，Line Search 缩减系数为 0.5。

如果平均 KL 超标，或者 Surrogate Objective 没有改善，就缩小 Step 再试。只有 Accept Update 后才把最终参数写入真正的 Actor；全部候选都失败则保留原 Weight。

15 · 对应 PyTorch：从 update 到最终写回参数

下列代码仅保留顺序和关键变量；gaes、fvp、conjugate_gradient 和 line_search 的完整实现沿用上面各节。它是带注释的流程骨架，不是独立可运行的训练脚本。

# (1) rollout 已经由 old actor 收集
with torch.no_grad():
    old_dist = Categorical(probs=actor(states))
    old_logp = old_dist.log_prob(actions)
    advantages = gaes(rewards, values, dones, gamma, lam)

# (2) 当前 actor == rollout 时的 actor；ratio 约为 1
new_logp = Categorical(probs=actor(states)).log_prob(actions)
ratio = (new_logp - old_logp).exp()
objective = (ratio * advantages).mean()

# (3) autograd 只算梯度，不调用 Adam 更新 Actor
g = flatten(torch.autograd.grad(objective, actor.parameters()))

# (4) KL Hessian-vector products + Conjugate Gradient
direction = conjugate_gradient(lambda v: fvp(v), g)

# (5) 根据 KL 约束缩放方向，再通过 Line Search 检查
candidate_step = scale_to_kl_limit(direction, kl_limit)
accepted_weights = line_search(
    actor, states, old_dist, old_logp, advantages, candidate_step
)

# (6) 唯一真正写回 Actor 的操作
vector_to_parameters(accepted_weights, actor.parameters())

16 · 四个常见误区

误区 1：KL 是筛选 Rollout 是否能用的开关？

不是。这里 Rollout 用来计算 Advantage 和 Gradient。KL 用来控制候选 Policy 相对旧 Policy 的变化。一次 Candidate 超标通常先缩小 Step，而不是丢掉 Rollout。

误区 2：Ratio=1，所以 Surrogate Objective 没有梯度？

Ratio 当前数值是 1，但 Ratio 仍是当前 Actor Weight 的函数，它的斜率通常非零。不能提前把 Ratio 替换成常量 1 再求导。

误区 3：CG 就是用新的 Learning Rate 训练网络？

不是。CG 只解线性方程得到方向；实际网络更新发生在 Line Search 接受参数并写回 Actor 后。Critic 则可以继续用 Adam。

误区 4：KL 小意味着真实 Reward 一定提高？

不是。KL 只度量分布变化；Surrogate Objective 也是基于有限采样和估计 Advantage 的近似。Line Search 检查的是 Surrogate Improvement，不是直接证明真实期望回报必然提高。
